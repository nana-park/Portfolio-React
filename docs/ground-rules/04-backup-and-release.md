# 백업과 릴리스

## 백업 원칙

Git에서는 파일 복사본이 아니라 커밋, 브랜치와 태그로 버전을 보관합니다.

- 기존 HTML 원본은 `nana-park/Portfolio` 저장소에 유지합니다.
- React 작업 중 이전 파일을 `backup/`, `old/`, `final/` 폴더에 복사하지 않습니다.
- 작은 단위로 커밋하여 언제든 이전 상태를 확인할 수 있게 합니다.
- 아직 공개하지 않을 작업은 기능 브랜치에 둡니다.
- 공개 시점은 태그로 고정합니다.

## 보호해야 하는 기준점

### 기존 HTML

기존 저장소에서 HTML 최종 운영본을 다음과 같이 보존하는 것을 권장합니다.

```text
브랜치: legacy-html
태그: html-v1-final
```

### React 최초 공개

React 사이트가 처음 공개될 때 다음 태그를 생성합니다.

```text
v2.0.0
```

이후 버전 예시:

```text
v2.1.0  새 페이지 또는 기능 추가
v2.1.1  기존 기능 오류 수정
v3.0.0  구조나 디자인의 큰 변경
```

## 배포 전 체크포인트

- 작업 브랜치의 변경 목적이 하나인지 확인
- 불필요한 이미지와 임시 파일이 포함되지 않았는지 확인
- 개발 서버에서 주요 화면 확인
- 프로덕션 빌드 성공 확인
- 모바일, 태블릿과 데스크톱 확인
- 링크, 이미지, 라우팅과 새로고침 확인
- 접근성 기본 항목 확인
- `beta`에서 통합 확인
- 릴리스 직전 버전 태그 준비

## 복구 원칙

운영 장애가 발생하면 현장에서 여러 파일을 임시 수정하기보다 마지막 안정 태그 또는 커밋으로 복구합니다.

1. 문제 발생 범위를 확인합니다.
2. 마지막 정상 릴리스 태그를 확인합니다.
3. 복구용 브랜치를 만듭니다.
4. 정상 버전을 다시 배포합니다.
5. 별도 `fix/*` 브랜치에서 원인을 수정합니다.
6. `beta` 검수 후 `main`에 반영합니다.

## 민감 정보

- `.env` 파일은 커밋하지 않습니다.
- API 키, 토큰과 개인 인증 정보는 GitHub에 올리지 않습니다.
- 공개 가능한 예시는 `.env.example`에 키 이름만 기록합니다.
